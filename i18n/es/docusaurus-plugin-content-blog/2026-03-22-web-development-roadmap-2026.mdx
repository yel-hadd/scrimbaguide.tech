# Roadmap de Desarrollo Web 2026: Una Ruta Práctica Lista para Trabajo

<DisclosureNotice />

Un **roadmap de desarrollo web** es una secuencia estructurada de habilidades a aprender, desde HTML básico hasta un portafolio listo para trabajo, organizado para maximizar la retención y minimizar el tiempo perdido en tutorial hell. En la práctica es cómo conviertes "estoy aprendiendo" en artefactos desplegables: cada etapa debe terminar en algo que puedas demostrar y defender en una llamada corta, no solo otra playlist que reconoces cuando se autocompleta.

Esta guía te da una ruta ordenada única, targets de horas, y una tabla de etapas que puedes pegar en tu plan de estudio.

Este roadmap está calibrado contra los cuatro career paths de Scrimba (Frontend, Fullstack, Backend, AI Engineer) y lo que las conversaciones de contratación realmente recompensan: fundamentos, práctica forzada, y luego artefactos públicos.

## Por qué el orden importa (y qué rompe la mayoría de aprendices) {#why-order-matters-and-what-breaks-most-learners}

Tutoriales al azar crean **memoria de reconocimiento**: asientes cuando ves código. Los trabajos requieren **memoria de recall**: produces una solución bajo leve presión. El fix es secuencia más output: aprende un slice, cierra la pestaña, reconstruye.

Nuestros [path overviews](/docs/paths/) desglosan estimaciones de horas para tracks Frontend, Fullstack, Backend, y AI Engineer para que puedas alinear este roadmap a un currículo concreto.

## Mapa de horas por etapa (baseline 2026) {#hours-per-stage-map-2026-baseline}

Usa esto como herramienta de presupuesto, no como carrera. Ajusta hacia abajo si ya conoces HTML o JS.

| Stage | Horas (guía) | Recurso orientado a Scrimba | Resultado |
| --- | ---: | --- | --- |
| Fundamentos HTML + CSS | 20 | Intros de HTML & CSS en la [Frontend Developer Path](/docs/paths/frontend-developer-path/) | Layouts estáticos y responsive que puedas explicar |
| Core de JavaScript | 30 | [Learn JavaScript](/docs/courses/javascript/learn-javascript/) + challenges | Apps DOM + async sin framework |
| React + patterns | 25 | [Learn React](/docs/courses/react/learn-react/) | Componentes reutilizables, hooks, routing |
| TypeScript | 15 | [Learn TypeScript](/docs/courses/typescript/learn-typescript/) | Refactores seguros; señal de stack job-ready |
| Portafolio (3 proyectos) | ~60–90 (6 semanas @ 10–15 h/wk) | Path capstones + builds solo | Demos desplegados + profundidad en README |
| Entrevista + aplicar | ~40–60 (4 semanas @ 10–15 h/wk) | [JavaScript interview challenges](/docs/courses/javascript/javascript-interview-challenges/) | Talk-track + aplicaciones consistentes |

Los totales para aprendizaje guiado en la tabla llegan cerca de **90 horas** antes de sprints de portafolio; la job readiness completa típicamente suma **semanas de building e iteración**.

## Etapa 1: HTML y CSS (alrededor de 20 horas) {#stage-1-html-and-css-about-20-hours}

Enfócate en **HTML semántico**, **Flexbox/Grid**, **breakpoints responsive**, y **patrones accesibles** (labels, focus, contrast). Salta perseguir cada framework de CSS a la vez, elige uno utility-first o librería de componentes después, una vez que puedas hand-code layout.

**Checkpoint:** Construye una landing page de un screenshot sin seguir un video.

## Etapa 2: Fundamentos de JavaScript (alrededor de 30 horas) {#stage-2-javascript-fundamentals-about-30-hours}

Prioriza **estructuras de datos en JS puro**, **DOM events**, **fetch + JSON**, y **async/await**. Toca build tools levemente (Vite es suficiente) así no estés bloqueado de desplegar.

**Checkpoint:** Una app pequeña que lea input del usuario, llame a una API pública, y maneje loading y error UI.

## Etapa 3: React y pensamiento de componentes (alrededor de 25 horas) {#stage-3-react-and-component-thinking-about-25-hours}

Aprende **un** modelo mental profundamente: function components, **props**, **useState/useEffect** (y cuándo *no* usar effects), y **composición de componentes**. Agrega **React Router** una vez que local state se sienta aburrido.

**Checkpoint:** Reconstruye un proyecto previo de vanilla JS en React desde una carpeta vacía solo con docs abiertos.

## Etapa 4: TypeScript (alrededor de 15 horas) {#stage-4-typescript-about-15-hours}

Introduce **interfaces**, **narrowing**, **union types**, y **generics** solo cuando resuelvan bugs reales en tu código React. Activa **strict** gradualmente.

**Checkpoint:** Migra un archivo de proyecto React por archivo con `tsc` clean.

## Etapa 5: Tres proyectos de portafolio (alrededor de seis semanas) {#stage-5-three-portfolio-projects-about-six-weeks}

Los hiring managers buscan **diferenciación**. Apunta a:

1. **UI product-shaped**, states, empty states, errors, loading.
2. **Integración de API**, keys manejadas de forma segura, suposiciones documentadas.
3. **Auth o persistencia**, incluso básica, muestra que puedes razonar sobre riesgo.

Reutiliza ideas de nuestro post [JavaScript projects for beginners (2026)](/blog/javascript-projects-for-beginners-2026/), pero personaliza scope.

## Etapa 6: Búsqueda de empleo y preparación para entrevistas (alrededor de cuatro semanas) {#stage-6-job-search-and-interview-prep-about-four-weeks}

Divide el tiempo **50/50** entre **articulación técnica** (explica tus repos) y **pipeline** (aplicaciones, intros cortas, follow-ups). Empareja lectura de comparaciones, p.ej. [Scrimba vs freeCodeCamp](/docs/comparisons/scrimba-vs-freecodecamp/), si estás eligiendo cuánta estructura necesitas mientras aplicas.

## Errores comunes en 2026 {#common-mistakes-in-2026}

- **Saltarse deployment**, Netlify/Vercel/GitHub Pages debería ser aburridamente familiar.
- **Framework antes de fundamentos**, El debug pain explota sin JS sólido.
- **Solo clones de tutoriales**, Los recruiters han visto la misma demo 500 veces.

## Git y colaboración (track paralela) {#git-and-collaboration-parallel-track}

No necesitas **advanced** Git en el día uno, pero deberías **temprano** sentirte cómodo con:

- **Branch-per-feature** workflow en repos personales.
- **Commits significativos** (subject lines imperativos, small diffs).
- **Pull requests** incluso solo, practica la narrativa.

El [Git and GitHub module](/docs/courses/javascript/git-and-github/) en este sitio se mapea a cómo los teams realmente revisan trabajo.

## Accesibilidad y calidad bar (hireable polish) {#accessibility-and-quality-bar-hireable-polish}

Accesibilidad no es un garnish de especialización, es **table stakes** para roles frontend. Hábitos mínimos viables:

- Controles interactivos navigables por teclado.
- Labels vinculados a inputs; visible focus states.
- Contraste de color que sobrevive salas de proyector.

Empareja eso con pensamiento de [accessible web design](/docs/courses/javascript/accessible-web-design/) una vez que tus layouts funcionen.

## Testing y confianza (sin ahogarse en tooling) {#testing-and-confidence-without-drowning-in-tooling}

Antes de que Jest domine tu semana, practica **characterization tests** en funciones puras y **manual test cards** para flows de UI. Agrega tests automatizados cuando los refactores duelen. Mira [unit testing](/docs/courses/javascript/unit-testing/) cuando estés listo.

## Señales de empleabilidad que hiring managers escanean {#employability-signals-hiring-managers-scan}

| Señal | Por qué importa |
| --- | --- |
| Live URL + repo link | Prueba que haces ship end-to-end |
| README con decisiones | Comunicación bajo incertidumbre |
| Commit history consistente | Disciplina, no heroísmo |
| Una feature no-tutorial | Diferenciación vs course clones |
