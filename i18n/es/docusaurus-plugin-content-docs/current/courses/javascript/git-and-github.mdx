## ¿Vale la pena tu tiempo? {#is-it-worth-your-time}

Casi todos los desarrolladores usan Git, y sorprendentemente muchos lo usan con nerviosismo, memorizando unos pocos comandos y entrando en pánico cuando algo sale mal. Este curso es la solución: enseña el flujo de trabajo y el modelo mental detrás de él, para que las ramificaciones, fusiones y colaboración dejen de parecer incantaciones. Con menos de dos horas, es una inversión pequeña para una habilidad que usarás literalmente en cada proyecto durante el resto de tu carrera.

La advertencia honesta es que este es un curso de flujo de trabajo, no un curso profundo de internals. Te permitirá ser productivo y confiado con Git y GitHub cotidiano, pero no cubrirá temas avanzados como estrategias de rebase en profundidad, modelos de objetos internos o políticas de ramificación complejas de equipos. Para la mayoría de desarrolladores ese es exactamente el alcance correcto; si querías Git internals, este no es ese.

## Qué aprenderás {#what-youll-learn}

El curso funciona a través del flujo de trabajo cotidiano de Git y GitHub como una historia conectada en lugar de una referencia de comandos. Aprendes cómo rastrear cambios con commits y por qué los commits pequeños y significativos importan, cómo las ramas te permiten experimentar sin romper tu trabajo principal, y cómo fusionar ese trabajo de vuelta. En el lado de GitHub cubres empujar tu trabajo a un repositorio remoto, colaborar en repositorios compartidos y el flujo de solicitud de extracción básico que los equipos usan para revisar y combinar cambios.

Porque se enseña interactivamente en el reproductor de Scrimba, ejecutas el flujo de trabajo en lugar de solo leerlo, lo que convierte a Git de una fuente de ansiedad en memoria muscular.

## Para quién es, y quién debe omitirlo {#who-its-for-and-who-should-skip-it}

Encaja con cualquier desarrollador que usa Git sin entenderlo realmente, y con cualquiera que se dirija hacia trabajo colaborativo o profesional donde las solicitudes de extracción y las ramas son la norma. Es ampliamente útil independientemente de que hagas frontend, backend o fullstack.

Omítelo si ya haces ramificaciones, fusiones, resuelves conflictos y ejecutas solicitudes de extracción cómodamente. De lo contrario, incluso usuarios de línea de comandos confiados a menudo encuentran que el marco del flujo de trabajo llena vacíos reales.

## Requisitos previos {#prerequisites}

La comodidad con la línea de comandos ayuda, ya que gran parte de Git ocurre ahí; el curso [Command Line Basics](/docs/courses/javascript/command-line-basics/) es un buen calentamiento si la terminal no te es familiar. No se asume ningún conocimiento previo de Git, y no se requiere ningún lenguaje de programación específico.
