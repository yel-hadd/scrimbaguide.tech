## ¿Vale la pena tu tiempo? {#is-it-worth-your-time}

Casi todos los desarrolladores usan git, y sorprendentemente muchos lo usan con nerviosismo, memorizando algunos comandos y entrando en pánico cuando algo sale mal. Este curso es la cura: enseña el flujo de trabajo y el modelo mental detrás de él, para que ramificar, fusionar y colaborar dejen de sentirse como conjuros. En menos de dos horas, es una inversión pequeña para una habilidad que usarás en prácticamente todos los proyectos por el resto de tu carrera.

La advertencia honesta es que este es un curso de flujo de trabajo, no un curso profundo de internals. Te hará productivo y seguro con el git y GitHub del día a día, pero no cubrirá temas avanzados como estrategias de rebase en profundidad, los modelos internos de objetos ni políticas complejas de ramificación en equipo. Para la mayoría de los desarrolladores ese es exactamente el alcance correcto; si buscabas los internals de git, este no es el curso.

## Qué vas a aprender {#what-youll-learn}

El curso recorre el flujo de trabajo cotidiano de git y GitHub como una historia conectada en lugar de una referencia de comandos. Aprendes a registrar cambios con commits y por qué importan los commits pequeños y significativos, cómo las ramas te permiten experimentar sin romper tu trabajo principal, y cómo fusionar ese trabajo de vuelta. Del lado de GitHub, cubres cómo subir tu trabajo a un remoto, colaborar en repositorios compartidos y el flujo básico de pull requests que usan los equipos para revisar y combinar cambios.

Como se enseña de forma práctica en el reproductor de Scrimba, ejecutas el flujo de trabajo en vez de solo leer sobre él, que es lo que convierte a git de una fuente de ansiedad en memoria muscular.

## Para quién es, y quién puede saltárselo {#who-its-for-and-who-should-skip-it}

Encaja con cualquier desarrollador que use git sin entenderlo del todo, y con quien se dirige hacia trabajo colaborativo o profesional donde los pull requests y las ramas son la norma. Es útil en general sin importar si haces frontend, backend o fullstack.

Sáltatelo si ya ramificas, fusionas, resuelves conflictos y ejecutas pull requests con comodidad. De lo contrario, incluso los usuarios seguros de la línea de comandos suelen encontrar que el enfoque de flujo de trabajo cubre vacíos reales.

## Requisitos previos {#prerequisites}

Tener comodidad con la línea de comandos ayuda, ya que gran parte de git ocurre ahí; el curso [Command Line Basics](/docs/courses/javascript/command-line-basics/) es un buen calentamiento si la terminal no te resulta familiar. No se asume conocimiento previo de git, ni se requiere un lenguaje de programación específico.
